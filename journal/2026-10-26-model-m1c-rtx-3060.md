## Resumable training (same evening)

kulo asked to keep working but postpone the long run, so the run now survives being split
into sessions.

- `train()` saves `last.pt` after every epoch (model, optimiser, AMP scaler, LR schedule,
  both RNG generators, epoch, best val accuracy), written to a `.partial` file and renamed so
  a kill mid-save keeps the previous one. It is deleted when all epochs are done.
- `geo-train run --resume` continues a paused or killed run; it refuses if there is nothing
  to resume or if any setting other than `--workers`/`--device` changed. A fresh run refuses
  to overwrite a folder holding an unfinished run.
- `geo-train run --max-hours H` pauses after the last epoch that fits in H hours (using the
  last epoch's duration) and exits without exporting.
- A progress line (seconds per step, minutes left in the epoch) goes to stderr every 500
  steps.
- New `packages/training/tests/test_resume.py`: a 3-epoch run paused after every epoch
  matches an uninterrupted run bit for bit (weights and history); plus the refusal cases and
  a CLI pause/resume to full export.
- Checks on this PC: `uv run pytest -q packages/training` → 49 passed; `uv run ruff check .`
  clean; audit passes. `uv run mypy` reports one error that exists before this change too
  (`torch.amp.GradScaler` not explicitly exported, torch 2.11 on Windows). The full
  `uv run pytest -q` has 4 failures outside the training package, also present before this
  change and Windows-only: a `cp1252` decode error (a file read without `encoding="utf-8"`)
  and `os.symlink` needing a privilege Windows withholds. `ruff format --check` lists 5
  files that were already unformatted; the new test file is formatted.
- Runbook section 4 now describes sessions with `--max-hours` and `--resume`, and uses the
  measured numbers.
