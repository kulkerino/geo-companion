# 2026-10-26 — Photo upload: the model's guess on your own photo

## Intent

M1c training is postponed to a weekend, and no GPU training runs in this session. Meanwhile,
let a learner upload a photo of their own and get the enabled model's top-3 country guess
or an abstention, through the existing `PredictionProvider` boundary. It works with the
dummy model now and with a real ONNX model once M1c exists.

## Evidence

- Branch: `feature/photo-upload`, cut from `feature/model-m1` at `ca3c50c`; the history of
  `feature/model-m1` is unchanged. Draft PR into `feature/model-m1`.
- What changed:
  - Contracts: `PhotoGuessResult` (model, candidates, abstained, origin `model_prediction`)
    with the same ranking and consistency rules as `ModelPredictionResult` (now a shared
    `check_candidates`); `PHOTO_UPLOAD_MEDIA_TYPES` (JPEG, PNG, WebP) and
    `PHOTO_UPLOAD_MAX_BYTES` (15 MB).
  - Providers: `PredictionProvider.predict_photo(bytes)`. The dummy seeds its placeholder
    scores from the file's bytes (same file, same answer; pixels never decoded). The ONNX
    provider decodes in memory with `image_input.decode_upload`: EXIF orientation applied,
    RGB, refused above 40 megapixels before decoding, then the same evaluation transform
    as rounds. An undecodable file raises `UnreadablePhotoError`.
  - API: `POST /api/v1/photo-guesses` takes the raw image as the request body, so no
    multipart dependency is added. It checks the content type (415), streams the body with
    a size cap (413), checks the leading bytes match the declared type (422), and returns
    404 when no model is enabled. The photo lives only in that request's memory: nothing is
    written to disk or SQLite, and there is no attempt or grading.
  - No-leak: an upload whose SHA-256 matches a loaded photo-pack asset is refused (409), so
    the model cannot be asked about a photo round before it is answered. Pack photos are
    re-encoded by `geo-train photo-pack`, so this catches the file the app itself serves; a
    re-saved copy still gets through (recorded as a known gap).
  - Generated client: `generate_api_contract.py` now types a binary request body as `Blob`
    and sends it with the Blob's own content type. `generated.ts` and `openapi.json` were
    regenerated by the script, not edited.
  - Web: a **Your photo** tab with a file picker, a local preview (object URL), **Ask the
    model**, and the same labelled opinion box as Compare with model. The copy says it is a
    guess, not an identification, and that the photo stays on this computer and is not
    saved. The combined-test ASGI bridge now carries binary bodies (base64 over its JSON
    lines).
  - Tests: `packages/api/tests/test_photo_upload.py` (13 tests: determinism, nothing stored,
    abstention, 415/413/422/404/409, the OpenAPI body, EXIF orientation and the pixel cap);
    an ONNX test that an upload ranks like the same file on disk; two component tests and
    one combined React → FastAPI → SQLite test.

  - `uv run pytest -q`: 139 passed, 1 skipped, 1 failed. The failure is

  - `uv run ruff check .`: passed. `uv run mypy`: no issues in 24 files.
  - `generate_api_contract.py --check` and `generate_starter_diagrams.py --check`: passed.
  - `npx --yes pnpm@11.19.0 install --frozen-lockfile`, then `--dir apps/web test`
    (11 passed), `lint`, `typecheck`, `build`: all passed.
  - `uv run python tools/audit_repository.py --root .`: passed.
  - Live check: uvicorn on `127.0.0.1:8765` with `GEO_COMPANION_MODEL=onnx:` the
    `m1c-gpu-smoke-2` manifest and a scratch data dir. 31 OSV-5M test photos posted with

- Decisions:
  - Raw body instead of multipart, to avoid a new dependency.
  - Uploads are never stored or graded: the learner's photo has no authored answer and
    may be personal.
  - The repository stays public (kulo: the professor needs it); `PROGRESS.md` said
    private and now says public.
- Limitations and external gaps:
  - No real top-3 on an upload yet: the only model on the PC always abstains. The ONNX
    top-3 path is covered by the tiny test model only.
  - Byte-identical refusal of pack photos only.
  - `test_web_bundle_safety` still needs `pnpm` on PATH on the PC.
